# Project verification

- Python environment: `mamba run -n ros_humble python ...`.
- On macOS use `mjpython pushup_upright.py` from the ROS environment for the MuJoCo viewer.
- Arduino sketch: `robot_recovery/robot_recovery.ino`; actor header: `robot_recovery/rl_actor_weights.h`.
- Export after training: `mamba run -n ros_humble python export_actor.py`.
- Firmware was compiled for `esp32:esp32:esp32` using ESP32 core 3.3.11 and ESP32Servo 3.2.1.
- Arduino CLI is bundled at `/Applications/Arduino IDE.app/Contents/Resources/app/lib/backend/resources/arduino-cli`.
- Compile from repository root: `"/Applications/Arduino IDE.app/Contents/Resources/app/lib/backend/resources/arduino-cli" compile --fqbn esp32:esp32:esp32 robot_recovery`.
- Documents-folder library access may be blocked by macOS. For isolated validation, install ESP32Servo 3.2.1 with `ARDUINO_DIRECTORIES_USER=/tmp/robot-recovery-arduino-validation` and use the same environment variable for compilation. Do not delete global library folders to work around access failures.
- Confirmed wiring: MPU6050 SDA 26, SCL 27; lower MG995 signal GPIO 25, upper GPIO 14.
- Current model contract is `direct_joint_targets_v1`: policy actions directly specify both joint targets at 50 Hz, bounded to +/-pi/2 with a 2 rad/s target slew limit. No scripted recovery actions, imitation pretraining, residual correction, timed homing, or upright target override are applied. MG995 dynamics remain approximate, not measured hardware identification.
- Train: `mamba run -n ros_humble python train_rl.py` (default 3 million steps). Selection checkpoint is `ppo_attachment_arm_direct.zip`; final optimizer state is `ppo_attachment_arm_direct_latest.zip`. Older residual checkpoints are incompatible and must not be exported as direct actors.
- Evaluate: `mamba run -n ros_humble python train_rl.py --evaluate --episodes 20`. Evaluation forces full side falls and counts sustained end-of-episode success, not transient peak uprightness. A minority of training resets start upright to learn balance; evaluation never does.
- Firmware defaults to `AUTO_ARM=false`; `R` enables direct policy control after calibration, countdown, and a stationary check. The actor continues balancing after standing. `H` remains a separate, explicitly requested center-pulse bench command, not a recovery phase. `C` retries calibration while disarmed/faulted and leaves recovery disarmed. Calibration requires 200 stationary valid samples and allows at most 10 short read dropouts with gaps no longer than 100 ms; motion or persistent read loss resets it.
- Run regression tests with `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 KMP_DUPLICATE_LIB_OK=TRUE mamba run -n ros_humble python -m pytest -q test/test_direct_policy.py test/test_actor_export.py`. Disabling plugin autoload avoids the installed ROS launch_testing plugin's incompatible pytest hook; it does not bypass repository checks.
- Export rejects legacy/unlabelled actors and normally requires held-out simulation validation. The header includes direct-control metadata, checkpoint SHA256, and simulation validation status; unvalidated diagnostic exports cannot arm policy recovery. Header and .ino must be uploaded together.
- Compilation and host tests do not establish physical recovery success; IMU mounting, servo zero, direction, pulse limits, and supply wiring require hardware checks. Do not flash or activate hardware without explicit authorization.
- Firmware diagnostic commands: `X` disarms; from INACTIVE, `T` runs a one-shot servo-only bench test with a three-second delay and center +/-100 microsecond pulses sequentially on GPIO25 and GPIO14, then detaches. Remove mechanical loads before this test. It explicitly bypasses IMU/RL; automatic recovery does not bypass sensor faults.
- Serial `Gate`, `LEDC_Hz`, and `DutyTicks` report software gating and ESP32 peripheral state, not physical servo feedback. MG995s have no position feedback.
- ESP32Servo 3.2.1 defaults to 10-bit PWM and resets timer width during attach. Firmware sets 16 bits after attaching, before writing the first pulse. At 50 Hz this reduces PWM quantization from 19.53 us to 0.305 us. Preserve this order on every reattachment; do not widen pulse endpoints to compensate for quantization.
- ESP32 core 3.3.11 `ledcReadFreq(pin)` returns zero when duty is zero, even if a timer is configured. Write the initial nonzero servo pulse before checking its frequency; checking before the first write caused a real `PWM_FREQUENCY_INVALID` startup fault. Host LEDC mocks must reproduce this behavior.
- Runtime telemetry uses bounded `logMessage`/`logLine` writes gated on `Serial.availableForWrite()`; do not restore blocking serial prints in the control path. Successful initial servo attachment restarts the control schedule, with a separate 500 ms initialization limit. The 100 ms running-loop stall shutdown remains enabled. `Timing` reports startup duration, last/fault loop gap, and dropped telemetry lines.
